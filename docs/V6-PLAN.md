## Report format (user rule 2026-09-30)
Every plan and every final report shows ALL FIVE sections in full: 1 Analyze · 2 Zones · 3 Wireframe · 4 Layers · 5 Confidence, then the SAP components table and "Approve / Reject / Modify?". Wireframe, layers and the components table are generated by
`node build/tree.js plan <tree>` (`build/sketch.js`; boxed sketch + `├─` tree for screens up to 600 px wide; wide screens keep the grid; `--grid` forces it). Never hand-drawn, never summarised.

## Why
v5 has the quality (EYE ≥ 95 %, MATCH ≥ 90, HYGIENE 0, STRUCTURE 0) but the run is slow and costly. Evidence: run 451:9507 = 219 turns / 34 min / $9.5 — every turn
re-sends the whole chat. The build itself is already fast and token-free (`send.js` → SAP Bridge plugin, ~11–90 s). The time went to: a hard human approval in the
middle (plan pasted verbatim, then a wait), a model loop editing `tree.json` until the door was happy, from-zero icon / ASK decisions, the model-typed fallback build,
and fat turns (PNGs, dumps). Headless Claude builds are banned: the same plan scored EYE 9–13 % headless vs 97 % interactive, and one headless run claimed EYE 97 for a measured 9.

## Design (how it was chosen)
3 independent architects (speed-first · determinism-first · product-first) → 3 adversarial judges (feasibility · quality · cost) → 1 synthesis. Winner: **build-first,
review-after**. Judge rulings kept: fix cap stays **2** (from-zero runs need round 2) · gold admission is approval-gated · the door runs on every path · a cold plugin
start is an honest human wait · text-only screens get a real lane · STRUCT-SIM is advisory (the simulator has no text wrapping).

## What v6 does
`node build/run.js <ref.png | "text"> --file <KEY> [--ask]` — one command:
1. t=0, parallel: bridge + plugin check ‖ `front.js` (see.py OCR · gold match · fit · door). If the plugin is closed, line 1 says so; the analysis keeps going and the job queues.
2. Image below 95 % gold coverage → `spec2tree` from the measured spec (from zero); unnamed icons → exit 2. Text job → skeleton + content ops (exit 2 until ops).
3. Door again on every path (+ `--baseline` geometry guard on resume) → asks triaged (only a screen-changing ask stops; the rest is an ASSUMED entry with its default) →
   layout-sim (position vs reference, overflow ×1 ×0.85 ×1.15) → STRUCT-SIM → logo crops.
4. `send.js` builds a frame named `DRAFT — <job>`; `gates.js` measures. `STATUS PASS|DRAFT · build n of 3 · elapsed`.
5. Report by the model: node link, measured gates, provenance, ASSUMED ledger with flip commands, the verbatim plan paste (rule 2026-09-29 kept, moved after the build).
6. Approve → `gold.js` promotes the tree (measured pass + door + `layout-sim --sizes` ≥ 90 %, never overwrites) → the next similar screen skips the think pass.

Exit codes: `0` PASS · `1` door / sim OUT · `2` the model must decide · `3` bridge down · `4` screen-changing ask (`--go` after the answer) · `5` `--ask` stop · `6` DRAFT / cap · `64` usage.
**Geometry (w h xy p g) of measured nodes is script-owned:** `door.js --baseline tree.baseline.json [--allow "<node>"]` rejects a model edit of it. Text lane = `reskin.js`
ops (`set` · `remove` · `clone`, no geometry keys). Verbs (`route.js`): `tweak · show · flip · gold · fix`. Flips that exist: `density` (Form Factor) and `text`.
